## 0. このドキュメントの位置づけ

元になっている AI プロジェクト用の指示文（以下「原指示文」）は、**AI が会話の中で毎回、過去問を取得・検証・採点・記録する**前提で書かれている。
アプリにする場合は、この役割を次のように分担し直すのが良い。

| 原指示文での担い手 | アプリでの担い手 | 理由 |
|---|---|---|
| AI が出典ページを見て問題を取得 | **事前に取り込み・検証済みの問題データベース** | 毎回の取得はハルシネーション・表記ゆれ・規約上のリスクが大きい |
| AI が解答を照合・再計算 | **取り込み時の検証ワークフロー**（人 or AI＋人のダブルチェック） | 出題時に検証するより、出題前に一度だけ確実に検証する方が正確 |
| AI が採点 | **アプリが機械的に採点**（正解記号との一致） | 4択の採点は決定的に行える。AI の介在は不要 |
| AI が学習履歴を会話内で管理 | **アプリがローカル／サーバーに永続保存** | 原指示文 §6・§7 の「永続保存を前提にしない」制約はアプリでは解消できる |
| AI が次の問題を選ぶ | **出題アルゴリズム**（重み付き抽選＋間隔反復） | 再現性・説明可能性があり、偏りも制御しやすい |
| AI が解説 | **検証済みの解説データ**＋（任意）AI による追加質問への回答 | 解説の正確性を担保しつつ、深掘りだけ AI に任せる |

原指示文の「正確性重視」「確認できないものは出さない」という思想は、**問題データに `検証ステータス` を持たせ、検証済みのものだけを出題対象にする**ことで実現する。

## 1. 試験制度の前提（2026年10月時点）

- AP は**令和8年度（2026年度）から CBT 方式へ移行**し、「午前」→**科目A**、「午後」→**科目B** に改称。出題範囲・形式・問題数・試験時間（各150分）は変更なし。
- 科目A：四肢択一 80問（全問必須）。科目B：記述式（11問中5問選択）。
- **令和7年度秋期がペーパー方式の最後の試験**。CBT 化後は試験問題が従来どおり公開されない可能性がある。
  → 原指示文の「直近3年を約3倍重視」は、**「公開済みの最新3年度（R5〜R7）」**を指すことになる見込み（要確認事項 Q7）。

## 3. 画面一覧と遷移

```
[ホーム] ──▶ [演習設定(任意)] ──▶ [出題] ──▶ [結果] ──▶ [詳しい解説]
   │                              ▲          │  │
   │                              └──次へ────┘  └──▶ [傾向分析] ──▶ [学習カルテ]
   ├──▶ [傾向分析]
   ├──▶ [論点一覧 / 苦手リスト]
   └──▶ [設定]（データのエクスポート/インポート・リセット等）
```

**UX 方針**

1. **モバイルファースト・片手操作**：主要ボタンは画面下部に配置（親指で届く範囲）。スキマ時間（通勤・休憩）の 1〜5 問演習を主シナリオにする。
2. **「すぐ解ける」**：ホームから 1 タップで出題開始。設定は「おまかせ」をデフォルトにし、こだわりたい人だけ演習設定を開く。
3. **誤タップ防止**：選択肢タップ → 「回答する」で確定の2段階。確定前は選択を変更できる。
4. **回答前に答えを漏らさない**（原指示文 §3）：出題画面には正解率・解説・ヒント・その問題の論点名も出さない（論点名がヒントになるため）。出典（年度・問番号）は表示可否を設定で選べるようにする。
5. **ラベルの一貫性**：過去問は「📘 過去問 R6秋 問23」、類題は「✏️ オリジナル類題」と、色＋アイコン＋文字の三重で区別（色覚多様性への配慮）。
6. **データの正直さ**（原指示文 §6・§7）：サンプル数が少ない集計には「参考値（n=7）」のように明示し、合格可能性を断定する表現はしない。

### 4.7 学習カルテ

- 50問ごとに自動でスナップショットを作成し、ホームに「学習カルテを更新しました」と通知。
- 内容：総合正答率／分野別正答率／弱点論点／習得済み論点／要復習論点／**今後の出題方針**（アルゴリズムの重み設定を文章化したもの）。
- 過去のカルテと比較できる（v1 → v2 の差分表示）。

### 4.8 問題の不備報告

- 理由選択：問題文の誤り／選択肢の誤り／正解が違う気がする／図が見えない／現行制度と異なる／その他（自由記述）。
- 報告された問題は**即座に採点保留**（正答率・習熟度の計算から一時除外）にするかは要確認（Q9）。
- 管理側で不備と確定したら：問題を出題停止、当該回答を全ユーザー分「採点除外」に変更し、統計を再計算（原指示文 §4「問題の不備による誤答はユーザーの誤答として記録しない」）。

Topic（論点）
  id, name, category, related_topic_ids[]

Attempt（回答記録）
  id, question_id, answered_at, choice, is_correct,
  confidence (sure | maybe | guess | null), gave_up (bool),
  time_spent_sec, excluded (bool), excluded_reason

TopicMastery（論点習熟度）← Attempt から再計算可能な派生データ
  topic_id, state (unseen | learning | review_due | mastered),
  correct_streak_distinct_questions, last_correct_at, next_review_at,
  interval_days, lapse_count

  question_id, reason, comment, created_at, resolution

- **TopicMastery は Attempt から常に再計算できる設計**にする。こうしておけば、問題の不備で採点除外したときも履歴を正しく修正できる（原指示文 §4）。

## 6. 出題アルゴリズム（案）

### 6.1 候補の絞り込み（ハード条件）

1. `verification.status = verified` の問題のみ（未検証・係争中・廃止は出さない）
2. **出題済みの問題は除外**（原指示文 §5）。例外は「全問出題し尽くした分野」で、そのときは最終回答から最も時間が経った問題を選ぶ（要確認 Q8）
3. 直前 2 問と同じ論点は除外（同じ論点の連続出題を防ぐ）
4. 誤答した問題そのものは再出題しない。復習は**同じ論点の別の問題**で行う

### 6.2 重み付け抽選（ソフト条件）

候補ごとに重み `w` を計算し、重みに比例してランダムに選ぶ（固定比率ではない＝原指示文 §1 の意図どおり）。

```
w = W_年代 × W_習熟 × W_バランス × W_難易度

W_年代     : 直近3年度 = 3.0、それ以前 = 1.0
             （古い問題でも、その論点が弱点なら W_習熟 で自然に引き上がる）
W_習熟     : 論点の状態に応じて
               review_due（復習期限到来）= 4.0
               learning（学習中）        = 2.0
               unseen（未学習）          = 1.5
               mastered（習得済み）      = 0.1（忘却チェック用にゼロにはしない）
W_バランス : 直近 N 問における分野の出題割合が、本試験の配分より多いほど下げる
             （例：テクノロジ約62% / マネジメント約12% / ストラテジ約25%）
W_難易度   : 直近の正答率が高ければ難しめ、低ければ易しめの問題を優遇
```

モード別の調整：「苦手克服を優先」は W_習熟 の review_due / learning を 2 倍に。「分野を指定」は分野外を除外。

### 6.3 なぜこの形か

- 重みが明示的なので、学習カルテの「今後の出題方針」として文章化できる。
- 数値は初期値。運用しながらチューニングする前提でパラメータ化しておく。

## 7. 習熟度の判定ルール（案）

原指示文の「異なる問題で安定して正解できた論点は習得済み」を具体的なルールにする。

| 状態 | 条件 |
|---|---|
| 未学習 unseen | その論点の回答なし |
| 学習中 learning | 回答があり、習得済みの条件を満たさない |
| 要復習 review_due | `next_review_at` を過ぎた／直近で誤答した |
| 習得済み mastered | **異なる 2 問以上で連続正解**、かつ 最後の正解が前回正解から **3日以上**空いている、かつ「勘」での正解は数えない |

**間隔反復**（SM-2 を簡略化したもの）

- 正解：次回の復習間隔を 1日 → 3日 → 7日 → 21日 → 60日 と伸ばす
- 誤答：間隔を 1日 に戻し、`lapse_count` を +1
- 誤答直後は同じ論点を出さず、最短でも **翌日以降 or 5問以上あと** に別の問題で確認（原指示文 §5「時間を空けて類題で確認」）
- 習得済みでも 60日経過で「忘却チェック」として低い重みで再出題対象に戻す

## 8. 問題データの整備方針（最重要）

### 8.1 出典について（要判断）

- 原指示文は主要ソースを **過去問道場（ap-siken.com）** としているが、同サイトの**解説文やページ内容は運営者の著作物**であり、アプリへの転載・スクレイピングは規約・著作権上の問題になりうる。
- 試験問題そのものの出典は **IPA が公開している過去問題（問題冊子・解答例 PDF）** を一次ソースとするのが安全。IPA の過去問利用条件（出典明記等）は利用前に最新の規定を確認する。
- 過去問道場は「参考リンク」として外部リンクで案内する程度に留めることを提案。

### 8.2 検証ワークフロー（原指示文 §2 のアプリ版）

```
取り込み(IPA PDF) → 構造化(問題文/選択肢/図) → 公式解答と照合
  → 独立に解き直し・計算問題は再計算/別解で検算 → 解説作成
  → 現行制度との差異チェック → ダブルチェック → verified
```

- 解説作成に AI を使う場合でも、**正解は IPA 公式解答を唯一の正**とし、AI の解答と食い違ったら人が確認する。
- 必要な問題数の目安：直近3年度（R5春〜R7秋 相当の 6 回 × 80問 ≈ 480問）＋それ以前の重要問題。まず **1〜2 回分（80〜160問）でMVP検証**するのが現実的。

## 9. 非機能要件（案）

| 項目 | 案 |
|---|---|
| プラットフォーム | **PWA（スマホのホーム画面に追加できる Web アプリ）** を推奨。1コードでスマホ・PC 両対応、ストア審査不要 |
| データ保存 | MVP は端末内（IndexedDB）。エクスポート/インポート（JSON）で機種変更に対応。同期は次期 |
| オフライン | 問題データを端末にキャッシュし、電車内でも演習可能に |
| アクセシビリティ | ダークモード、文字サイズ変更、色だけに頼らない正誤表示 |
| 図版 | 問題の図は画像＋拡大表示。表は可能な限りテキスト化 |
