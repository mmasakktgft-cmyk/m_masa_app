## 0. 基本方針（決定事項）

| 項目 | 決定 |
|---|---|
| 利用者 | **自分専用**（ログインなし） |
| 形態 | **PWA**（スマホのホーム画面に追加できる Web アプリ。オフラインでも演習可） |
| 実行時の AI 利用 | **なし**。API キー不要、従量課金なし |
| 問題・解説データ | **開発時に Claude Code で作成・検証**し、JSON としてアプリに同梱（今のご契約の範囲内） |
| 解説の深掘り | 結果画面の「Claude に質問」ボタンで質問文をクリップボードにコピー → Claude アプリに貼り付け |
| ランニングコスト | **0 円**（無料ホスティング） |

元の指示文（以下「原指示文」）の役割は、次のように振り分ける。

| 原指示文での担い手 | アプリでの担い手 |
|---|---|
| AI が出典ページから問題を取得・検証 | 開発時に **IPA 公開 PDF から取り込み、検証済みのものだけ同梱** |
| AI が採点 | アプリが正解記号と照合して採点 |
| AI が次の問題を選ぶ | 出題アルゴリズム（§6） |
| AI が会話内で履歴を管理 | 端末内（IndexedDB）に永続保存 |
| AI が解説 | 同梱の検証済み解説＋深掘りは Claude チャットへ |

## 1. 試験制度の前提（2026年10月時点）

- AP は**令和8年度から CBT 方式**に移行し、午前→**科目A**、午後→**科目B** に改称。出題範囲・形式・問題数・試験時間（各150分）は変わらない。
- 科目A：四肢択一 80問。科目B：記述式（11問中5問選択）。
- **令和7年度秋期がペーパー方式の最後の試験**。CBT 化後は問題が公開されない可能性がある。
- 本アプリの「直近3年」は **公開済みの最新3年度＝R5春〜R7秋（6回分・約480問）** と定義する。

## 3. 画面一覧と遷移

```
[ホーム] ──▶ [演習設定(任意)] ──▶ [出題] ──▶ [結果] ──▶ [詳しい解説]
   │                              ▲          │  │
   │                              └──次へ────┘  └──▶ [傾向分析] ──▶ [学習カルテ]
   ├──▶ [傾向分析]
   ├──▶ [論点一覧]（論点ごとの習熟度・次回復習日）
   └──▶ [設定]（エクスポート/インポート・リセット・表示設定）
```

**UX 方針**

1. **スマホで片手操作**：主なボタンは画面下部。1〜5問のスキマ時間演習を主な使い方とする。
2. **すぐ解ける**：ホームから1タップで出題。設定は「おまかせ」が既定。
3. **誤タップ防止**：選択肢を選ぶ →「回答する」で確定。確定前は選び直せる。
4. **回答前は答えを漏らさない**：正解率・解説・ヒント・**論点名**は回答後に表示。出典（年度・問番号）を出題時に表示するかは設定で選べる。
5. **過去問とそれ以外の区別**：色・アイコン・文字の3つで区別（色覚の多様性に配慮）。
6. **データに正直**：サンプル数が少ない集計は「参考値（n=7）」と明示。合格可能性は断定しない。
7. **ダークモード・文字サイズ変更**に対応。

- 50問ごとに自動作成し、ホームで通知。総合・分野別正答率／弱点／習得済み／要復習／**今後の出題方針**（§6 の重みを文章化）。
- 前回のカルテとの差分を表示。

### 4.9 不備報告

- 理由：問題文の誤り／選択肢の誤り／正解が違う気がする／図が見えない／現行制度と違う／その他（自由記述）。
- 自分専用なので、**報告した時点でその問題を出題停止し、回答を採点から除外**（正答率・習熟度を再計算）。設定画面から取り消せる。
- 報告内容はエクスポートでき、開発側（Claude Code）でデータを修正する際に使う。

## 6. 出題アルゴリズム

### 6.1 候補の絞り込み

1. `verification.status = verified` の問題のみ
2. **一度出題した問題は出さない**（全問を出し終えた場合の扱いは Q8）
3. 直前2問と同じ論点は出さない
4. 誤答した問題そのものは出さない。復習は**同じ論点の別の問題**で行う

### 6.2 重み付き抽選

```
w = W_年代 × W_習熟 × W_バランス × W_難易度

W_年代     : R5春〜R7秋 = 3.0、それ以前 = 1.0
W_習熟     : 要復習 4.0 / 学習中 2.0 / 未学習 1.5 / 習得済み 0.1
W_バランス : 直近の出題に占める分野の割合が本試験の配分より多いほど下げる
W_難易度   : 直近の正答率が高ければ難しめ、低ければ易しめを優遇
```

- 「苦手克服を優先」モードでは、要復習・学習中の重みを2倍にする。
- 重みはパラメータとして定義し、運用しながら調整する。

## 7. 習熟度の判定ルール

| 状態 | 条件 |
|---|---|
| 未学習 | 回答なし |
| 学習中 | 回答はあるが習得済みの条件を満たさない |
| 要復習 | 次回の復習日を過ぎた／直近で誤答した |
| 習得済み | **異なる2問以上で連続正解**、かつ正解の間が**3日以上**空いている、かつ「勘」の正解は数えない |

- 復習の間隔：正解ごとに 1日 → 3日 → 7日 → 21日 → 60日 と伸ばす。誤答で 1日 に戻す。
- 誤答の直後は同じ論点を出さず、**翌日以降または5問以上あと**に別の問題で確認。
- 習得済みでも60日経ったら、忘れていないかの確認として低い重みで出題候補に戻す。

## 8. 問題データの作成手順（開発時・Claude Code）

### 8.1 出典

- 一次ソースは **IPA が公開している過去問題（問題冊子・解答例 PDF）**。IPA は公表済み過去問題の使用について、原則として許諾・使用料を不要としている（使用時の留意点は IPA の FAQ を実装前に確認する）。
- 過去問道場（ap-siken.com）の解説やページ内容は運営者の著作物のため、**転載しない**。

### 8.2 手順

```
① IPA の問題冊子 PDF・解答例 PDF を取得
② 問題文・選択肢・図を構造化（図は画像として切り出し）
③ 正解は IPA 解答例を唯一の正とする
④ Claude が独立に解き直し、③と一致するか照合（計算問題は再計算＋別解で検算）
⑤ 解説・各選択肢の要点・間違えやすい点・論点・分類を作成
⑥ 現行の制度・法令との差異をチェック
⑦ 別の観点からもう一度レビュー（④〜⑥の見直し）
⑧ すべて通ったものだけ verified。食い違いや曖昧さがあれば disputed として出題しない
```

- 作業の順番：**まず R7秋の1回分（80問）で MVP を作って動作を確認** → 残りの R5春〜R7春 → 必要に応じてそれ以前の重要問題。
- **前提**：このクラウド環境は現在 **www.ipa.go.jp へのアクセスが遮断されている**。データを作成するには次のどちらかが必要（Q12）。
  - (a) 環境のネットワーク設定で `www.ipa.go.jp` を許可する
  - (b) PDF をこちらにアップロードしていただく

## 9. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | React + TypeScript + Vite | 情報量が多く保守しやすい |
| PWA | vite-plugin-pwa | オフライン対応・ホーム画面に追加 |
| 端末内の保存 | IndexedDB（Dexie.js） | 大量の回答記録も扱える |
| グラフ | 自作の軽量 SVG／CSS | 依存を減らし軽くする |
| テスト | Vitest | 出題アルゴリズム・習熟度判定・集計を重点的にテスト |
| 問題データ | `public/data/*.json`＋図の画像 | 年度ごとに分割して読み込む |
| ホスティング | **Cloudflare Pages（無料）** | リポジトリが非公開でも無料で公開できる（GitHub Pages は非公開リポジトリだと有料プランが必要） |

- 公開 URL は誰でも開ける状態になる（検索には載せない）。気になる場合は Cloudflare Access（無料枠）で自分だけに制限できる（Q13）。
- 学習データは端末の中だけに保存される。**ブラウザのデータを消すと履歴も消える**ため、設定画面からのエクスポートを定期的に促す。
